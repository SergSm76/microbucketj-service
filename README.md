## microbucketj-service

**MicroBucketJ** — распределённый сервис ограничения скорости запросов (rate limiter) на Java, построенный на Netty. Позволяет ограничивать интенсивность запросов к API с помощью настраиваемых лимитирующих «бакетов» (token bucket), работая как в одиночном режиме, так и в кластере.

### Основные возможности

- **Распределённый rate limiting** — настраиваемые бакеты с ёмкостью, скоростью пополнения и периодом (`RLS_BUCKETS`), включая ступенчатые лимиты (step-capacities).
- **Кластеризация и репликация** — несколько реплик на бакет (`REPLICA_COUNT`), настраиваемое минимальное число подтверждений записи (`MIN_ACKS`), режимы кворума и репликации.
- **Автоматическое обнаружение узлов** — через DNS (`DISCOVERY_DNS`) или статический список хостов (`DISCOVERY_HOSTS`).
- **Отказоустойчивость** — heartbeat-мониторинг узлов, выбор лидера, повторные подключения и таймауты.
- **Гибкое публичное API** — операции acquire/report по имени или хэшу ключа, упрощённые варианты запросов, управление бакетами (upsert/get).
- **Наблюдаемость** — метрики Prometheus и HTTP-эндпоинты observability (`OBSERVABILITY_PORT`).
- **Безопасность** — поддержка TLS/mTLS для внутренней кластерной коммуникации.
- **Конфигурация через переменные окружения** — без изменения кода.


# Индивидуальные переменные окружения для запуска сервиса microbucketj-service

* `${PUBLIC_PORT}` - Порт, на котором сервис принимает внешние клиентские запросы 
* `${CLUSTER_PORT}` - Порт для внутренней кластерной коммуникации 
* `${REPLICA_COUNT}` - Количество реплик для каждого бакета (должно быть > 0)
* `${RLS_BUCKETS}` - Конфигурация лимитирующих бакетов (пример: "api:ver=1,cap=300,refill=300,periodMs=1000,step-capacities=100,200,step-period=5000,not-used=60000")
* `${IO_THREADS}` - Количество потоков ввода-вывода для обработки сетевых операций (количество ядер CPU, но не менее 2 и не более 4)
* `${MIN_ACKS}` - Минимальное количество подтверждений от реплик, необходимых для признания записи успешной (по умолчанию: `0`)

* `${DISCOVERY_DNS}` - DNS-имя сервиса для автоматического обнаружения узлов кластера (значение: '' (пусто) для запуска в одном экземпляре или '${SERVICE-NAME}' для запуска в кластере)
* `${DISCOVERY_HOSTS}` - Список хостов и портов других узлов кластера (формат: "host1:port1,host2:port2", пример для локального запуска: "127.0.0.1:8096")

* `${BIND_HOST}` - Хост, на котором сервис будет слушать входящие соединения (по умолчанию: `0.0.0.0`)
* `${HOST_IP}` - Хост, который будет объявляться другим узлам кластера (по умолчанию: `127.0.0.1`)

* `${POD_NAME}` - Уникальный идентификатор узла кластера (по умолчанию: `n1`)

* `${PUBLIC_MAX_FRAME}` - Максимальный размер фрейма запроса для публичного интерфейса (по умолчанию: `4096`)
* `${INTERNAL_MAX_FRAME}` - Максимальный размер фрейма запроса для внутреннего интерфейса (по умолчанию: `65536`)

* `${RECONNECT_PERIOD_MS}` - Интервал повторной попытки подключения к узлу (по умолчанию: `1000`)
* `${HEARTBEAT_INTERVAL_MS}` - Интервал отправки heartbeat-сообщений (по умолчанию: `1000`)
* `${HEARTBEAT_TIMEOUT_MS}` - Таймаут считать узел мёртвым после отсутствия heartbeat (должен быть ≥ 2×HEARTBEAT_INTERVAL_MS, по умолчанию: `3000`)
* `${LEADER_HOLD_DOWN_MS}` - Время, в течение которого узел не может стать лидером после потери статуса (по умолчанию: `500`)
* `${OBSERVABILITY_ENABLED}` - Включить/отключить метрики и мониторинг (по умолчанию: `true`)
* `${OBSERVABILITY_PORT}` - Порт для эндпоинтов observability (по умолчанию: `8083`)

* `${MTLS_ENABLED}` - Включить TLS/MTLS для внутренней коммуникации (по умолчанию: `false`)
* `${KEYSTORE_LOCATION}` - Путь к файлу keystore для TLS (по умолчанию: пусто)
* `${KEYSTORE_PASSWORD}` - Пароль для keystore и ключа (по умолчанию: пусто)
* `${KEYSTORE_TYPE}` - Тип keystore (по умолчанию: `PKCS12`)
* `${TRUSTSTORE_LOCATION}` - Путь к файлу truststore для TLS (по умолчанию: пусто)
* `${TRUSTSTORE_PASSWORD}` - Пароль для truststore (по умолчанию: пусто)
* `${TRUSTSTORE_TYPE}` - Тип truststore (по умолчанию: `PKCS12`)
